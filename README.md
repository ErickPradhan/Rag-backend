# Palm Mind RAG Backend

A FastAPI backend with two REST APIs:

1. **Document Ingestion** – upload `.pdf` / `.txt`, extract text, chunk it (2 selectable strategies), embed it, store vectors in **Qdrant**, store metadata in **SQL (SQLite)**.
2. **Conversational RAG** – custom retrieval pipeline (no `RetrievalQAChain`), **Redis** chat memory, multi-turn questions, and **interview booking** (name, email, date, time) driven by the LLM. Bookings are stored in SQL.

No FAISS, no Chroma, no UI.

## Architecture

```
app/
  main.py            app startup
  config.py          settings from .env
  db.py              SQL tables: documents, bookings
  schemas.py         request/response models
  deps.py            builds shared services
  routers/
    ingestion.py     POST /documents/ingest
    chat.py          POST /chat, GET /bookings
  services/
    extraction.py    PDF/TXT -> text
    chunking.py      "fixed" and "sentence" strategies
    llm.py           chat + embeddings (OpenAI-compatible API)
    vector_store.py  Qdrant
    memory.py        Redis chat history + pending booking
    ingestion.py     ingestion pipeline
    chat_service.py  RAG + booking logic
tests/               unit + end-to-end tests (fake LLM/Redis)
```

### How a chat message is handled
1. Load the last messages from Redis.
2. One LLM call decides: *question* or *booking?* It also rewrites follow-ups ("what about its price?") into a standalone question and pulls out any booking details.
3. **Question** -> embed -> search Qdrant -> LLM answers using only the retrieved text + chat history.
4. **Booking** -> merge new details with those already collected (kept in Redis), validate email/date/time, ask for whatever is missing, and save to SQL once complete.

## Setup

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate      Mac/Linux: source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env        # then put your API key inside .env
docker compose up -d        # starts Redis (or use a free Upstash Redis URL)
uvicorn app.main:app --reload
```

Open http://localhost:8000/docs to try both APIs in the browser (auto-generated by FastAPI).

Qdrant needs no setup: with `QDRANT_URL` empty it stores vectors in a local `qdrant_data/` folder. Set `QDRANT_URL` / `QDRANT_API_KEY` to use Qdrant Cloud instead.

## Example calls

```bash
# 1) Ingest (chunking_strategy = fixed | sentence)
curl -X POST http://localhost:8000/documents/ingest \
  -F "file=@sample.pdf" -F "chunking_strategy=sentence"

# 2) Chat (omit session_id on the first message; reuse the returned one afterwards)
curl -X POST http://localhost:8000/chat -H "Content-Type: application/json" \
  -d '{"message": "What does the document say about refunds?"}'

curl -X POST http://localhost:8000/chat -H "Content-Type: application/json" \
  -d '{"session_id": "<ID>", "message": "I would like to book an interview. I am Ram, ram@mail.com, tomorrow at 3pm"}'

# 3) See stored bookings
curl http://localhost:8000/bookings
```

pytest

## Design notes
- Chunking: `fixed` = 800 chars with 100 overlap; `sentence` = whole sentences packed up to 800 chars.
- Any OpenAI-compatible provider works via `LLM_BASE_URL` (Gemini by default, OpenAI also fine).
- SQLite keeps setup simple; change `DATABASE_URL` to use PostgreSQL.
